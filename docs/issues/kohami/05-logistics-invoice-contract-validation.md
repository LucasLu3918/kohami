# 05: 建立模擬物流與交易憑證契約

**What to build:** 實作示意運費、模擬配送與無稅務效力憑證契約，不串接服務商。

**Blocked by:** 02：確認配送、售後與發票規則

**Status:** ready-for-agent

- [ ] 提供版本化示意費用表與有效／無效區域情境；無有效費用不得確認，歷史快照不可覆寫。
- [ ] 模擬配送合法轉移、重送／亂序及異常恢復可驗證；不提供真實承運追蹤或寄送功能。
- [ ] 建立 DEMO 憑證、部分／全額調整、失敗／未知及查詢重試；明示無稅務效力，退款與憑證狀態分開。
- [ ] 提供18／21可使用的情境契約與證據；真實運費、資格、物流／發票服務商與沙盒延期，不當作本階段開發前置。

## 來源與範圍

- 階段：前置決策與實證。
- 驗收對應：V05；User Stories 16、26、29、77。
- 基準：KOHAMI 核心商店與模特換裝參考規格 v0.1（含 Comments）、產品規劃書、術語表、現行決策 D396–D446、驗證計畫及 ADR-0001；遵循 Round 18，有效決策不等於歷史編號總數。
- 先確認阻擋票均已完成；`ready-for-agent` 不解除依賴或重大待決條件。前置票須提供可審查證據並完成必要決策確認，不能把 UNKNOWN 或 PROVISIONAL 改寫成既定事實。
- 本票有實作時，按確認旅程補齊必要資料、介面、畫面、權限與錯誤行為，再驗證輸入、輸出、資料、事件及消費者影響；不拆成單獨的 schema／API／UI 層票。
- 沿用已確認測試接縫：瀏覽器端到端旅程為主；付款事件、庫存競爭與復原另用必要外部邊界驗證；素材品質及權利保留人工審核。執行前均屬 NOT_EXECUTED，不以圖片載入或工具成功當成所有驗收通過。
- 票單採用僅批准本機議題建立；後續工作依當次授權與必要決策執行。實作、付費／採購、素材製作、正式部署收款及換裝啟用不得僅由票單狀態推定授權；Phase 3／4 另案處理。

## 正式串接延期清單（原驗收條件，非本階段阻擋）

- [ ] 以同一配送及退款情境查核候選服務的申請條件、運費、重量／體積限制、物流狀態及發票介面，保留日期、來源與限制。
- [ ] 於授權測試環境驗證配送事件重送／亂序、失敗恢復，以及交易、取消、退款與發票處理的一致性。
- [ ] 確認服務商及政策相容性，列出事件、查詢、錯誤及恢復契約；尚未取得資格或證據的項目維持未通過。
- [ ] 正式採購、申請、寄送與發票開立依當次授權，不把查核或沙盒結果當成正式營運批准。
