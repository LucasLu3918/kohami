# 04: 建立模擬金流契約與情境驗證

**What to build:** 實作受控後端 mock 付款／退款契約，保留未來真實服務商選型清單。

**Blocked by:** 01：確認結帳與庫存交易規則；02：確認配送、售後與發票規則

**Status:** ready-for-agent

- [ ] 實作模擬付款／退款、查詢與台帳契約，識別模式、資料集、訂單、操作、金額／幣別與事件版本；顧客顯示模擬結果。
- [ ] 驗證成功、明確拒絕、未知、重複／亂序、金額不符及晚到成功；前台不能自行偽造已付款或已退款。
- [ ] 重送去重、退款額度保留、原交易關聯與結果查核可重現；無外部收款或供應商 API 呼叫。
- [ ] 輸出可供13–15／20使用的 adapter 情境與驗證證據；真實資格、費率、服務商沙盒列延期清單，不假稱完成。

## 來源與範圍

- 階段：前置決策與實證。
- 驗收對應：R03–R05／AC03–AC05；V04；User Stories 20–25、75–76。
- 基準：KOHAMI 核心商店與模特換裝參考規格 v0.1（含 Comments）、產品規劃書、術語表、現行決策 D396–D446、驗證計畫及 ADR-0001；遵循 Round 18，有效決策不等於歷史編號總數。
- 先確認阻擋票均已完成；`ready-for-agent` 不解除依賴或重大待決條件。前置票須提供可審查證據並完成必要決策確認，不能把 UNKNOWN 或 PROVISIONAL 改寫成既定事實。
- 本票有實作時，按確認旅程補齊必要資料、介面、畫面、權限與錯誤行為，再驗證輸入、輸出、資料、事件及消費者影響；不拆成單獨的 schema／API／UI 層票。
- 沿用已確認測試接縫：瀏覽器端到端旅程為主；付款事件、庫存競爭與復原另用必要外部邊界驗證；素材品質及權利保留人工審核。執行前均屬 NOT_EXECUTED，不以圖片載入或工具成功當成所有驗收通過。
- 票單採用僅批准本機議題建立；後續工作依當次授權與必要決策執行。實作、付費／採購、素材製作、正式部署收款及換裝啟用不得僅由票單狀態推定授權；Phase 3／4 另案處理。

## 正式串接延期清單（原驗收條件，非本階段阻擋）

- [ ] 用相同交易情境查核候選金流的申請資格、付款方式、費用、通知驗證、主動查詢、退款及對帳契約，記錄日期、官方來源與限制。
- [ ] 在已授權且不正式收款的沙盒中驗證重送、逾時、未知結果、通知亂序及晚到成功；不偽造內部訂單或庫存結果。
- [ ] 列出費率與能力比較、推薦與風險，取得服務商及重大交易條件確認；無實證不得標記通過。
- [ ] 輸出可供後續付款旅程使用的請求／事件、可信性、錯誤、重試／冪等及對帳契約；付費、開戶與正式收款另依實際授權。
