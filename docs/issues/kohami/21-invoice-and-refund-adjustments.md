# 21: 交易憑證與退款發票處理

**What to build:** 顧客取得符合已確認規則的憑證；取消、退貨及退款對應正確發票處理，失敗可恢復。

**Blocked by:** 20：受控退款與財務核對

**Status:** ready-for-agent

- [ ] 依現行 mock 契約，在隔離測試資料集由受控交易結果建立無稅務效力 DEMO 憑證，顧客可查閱自己的資料。
- [ ] 取消、退貨、部分／全部退款建立模擬憑證調整，不宣稱有效稅務作廢或折讓，金額與原交易／退款一致。
- [ ] 重送、服務拒絕與結果未知可查詢、重試或進入例外，不重複建立有效憑證處理。
- [ ] 核對資料存取、營運稽核及財務對帳；正式開票另依實際營運授權。

### 2026-10-14 實作紀錄

- 憑證識別以 `DEMO-` 開頭，明示無稅務效力；付款成功與退款成功才產生相應紀錄，退貨／退款狀態分開呈現。
- 退款成功交易會另建 DEMO 調整工作；憑證調整由後續 worker 工作獨立處理，可呈現成功／失敗／未知，並以受權限保護的 mock 情境重試，不回寫退款狀態。
- SQL／瀏覽器旅程未執行，故尚未用故障注入證明調整失敗不影響退款；驗收清單維持未勾選。

### 2026-10-15 SQL 驗收補充

- `Commerce.Tests` 專用 `demo_m0` SQL runner 已驗證退款成功產生唯一 DEMO 調整工作、worker 依目標 Job ID 完成調整，顧客收據查詢呈現 `Adjusted` 且 `taxEffect=none`。與配送／退貨／退款流程合計 45 項檢查全數通過。
- 此為 service＋SQL 成功路徑；HTTP middleware、瀏覽器、調整失敗／未知結果、去重重試及正式稅務效力仍未驗。原驗收清單維持未勾選。

### 2026-10-15 未知結果與重試補驗

- 專用 `demo_m0` SQL runner 增至 49 項檢查全數通過。DEMO 調整未知時不回滾已成功退款；受控 mock 情境可重試同一調整，最終只有一筆無稅務效力的 `Adjusted` 紀錄，也不會重建或重送退款。
- 此為合成 SQL／service／worker 驗證，未驗真實 HTTP middleware、Owner／MFA、瀏覽器、外部憑證服務或稅務效力；Issue 21 驗收清單與 Work status 維持未變。

## 來源與範圍

- 階段：Phase 1 核心商店。
- 驗收對應：User Stories 29、76–77；V05。
- 基準：KOHAMI 核心商店與模特換裝參考規格 v0.1（含 Comments）、產品規劃書、術語表、現行決策 D396–D446、驗證計畫及 ADR-0001；遵循 Round 18，有效決策不等於歷史編號總數。
- 先確認阻擋票均已完成；`ready-for-agent` 不解除依賴或重大待決條件。前置票須提供可審查證據並完成必要決策確認，不能把 UNKNOWN 或 PROVISIONAL 改寫成既定事實。
- 本票有實作時，按確認旅程補齊必要資料、介面、畫面、權限與錯誤行為，再驗證輸入、輸出、資料、事件及消費者影響；不拆成單獨的 schema／API／UI 層票。
- 沿用已確認測試接縫：瀏覽器端到端旅程為主；付款事件、庫存競爭與復原另用必要外部邊界驗證；素材品質及權利保留人工審核。執行前均屬 NOT_EXECUTED，不以圖片載入或工具成功當成所有驗收通過。
- 票單採用僅批准本機議題建立；後續工作依當次授權與必要決策執行。實作、付費／採購、素材製作、正式部署收款及換裝啟用不得僅由票單狀態推定授權；Phase 3／4 另案處理。
