## Problem Statement

顧客需要在手機上以熟悉的語言查看日系服飾的真實照片、顏色、尺寸與價格，並完成可追溯的付款、配送及售後。一般商品照片難以幫助顧客理解不同模特身形與視角下的服裝外觀；同時，換裝展示不能讓顧客誤認商品有庫存、已選好購買尺碼或保證本人合身。

營運人員需要一致的商品、庫存、付款與履約資訊，避免超賣、重複有效交易及未知付款結果。角色與服裝素材必須有合法來源、正確版本和可獨立停用的機制，才能持續提供可靠的外觀參考。

目前工作目錄只有規劃文件，沒有應用程式、Git Repository、API、資料庫或既有可執行測試。企劃保留的品牌、平台、供應商、成本及若干交易政策仍待驗證；將候選寫成既定選型會讓後續開發建立在未確認的條件上。

## Solution

建立以台灣為初期市場、TWD 交易、手機優先的單一品牌 B2C 日系服飾商店，提供繁體中文、日文與英文內容。顧客可從真實商品資訊完成訪客或會員購物，查看可信付款狀態、配送與售後；營運人員依授權管理商品、庫存、交易、內容與素材。

Phase 1 先完成可獨立營運的核心商店；Phase 2 在授權、品質、效能與支援範圍通過驗收後加入免費的「模特換裝參考」。此功能使用事前準備的非 AI 固定 2D／2.5D 資產，提供四組成年標準模特及公告尺寸的正面、右側面、背面。顧客自行選擇角色身形與商品 SKU，查看合格組合，主動保存穿搭或下載授權示意截圖。換裝失效時仍能使用真實照片、尺寸表與正常購物流程。

本次規格整理不改變既有產品決策。完整產品實作屬有條件適合：核心商店需補齊交易與服務契約；固定換裝需取得合格素材及實測證據。先完成規格審查與必要決策，再將可執行範圍交給工程 agent。

## Implementation Decisions

- **現行基準**：採企劃 R01–R20、現行 D396–D446 的有效決策及 ADR-0001。D399 休眠；收藏數量、互動效能與商業數字保留其暫定／待驗證狀態。歷史編號上限 446 不代表 446 項有效規則。
- **交付順序**：Phase 1 建立核心商店；Phase 2 加入固定換裝、明確收藏與授權匯出。Phase 3 營運優化與 Phase 4 國際擴充另案處理。完整線框、視覺系統及可及性規格仍需完成。
- **商品模組 Catalog**：Product 表示商品款式；SKU 表示真實顏色／服裝尺寸組合的唯一商務規格。商品款數、SKU 數與素材組合數分開管理。三語內容及售價由商務權威資料提供。
- **庫存模組 Inventory**：區分可銷售庫存、Reservation 與 Movement；不可重複承諾同一庫存。具體保留期限、釋放規則及並行處理尚未定案。
- **結帳與訂單模組 Checkout／Order**：交易前重新驗證 SKU、金額與庫存。重送不得建立重複有效交易；已付款訂單保留 Price Snapshot，不能被現行商品改價覆寫。TWD 金額計算、優惠與費用分攤必須精確且可重現；精度契約及疊加政策待詳規。
- **付款模組 Payment**：Payment Attempt 不等於 Order 或已收款。以可信通知、主動查詢與對帳確認結果；未知結果顯示待確認。取消或保留到期後收到成功結果需走補償，不能直接恢復訂單造成超賣。退款上限、核准、事件重送及狀態轉移待確認的契約。
- **履約模組 Fulfillment**：Shipment、Return 與 Inspection 協調配送、退貨與驗收；發票作業需與交易及退款一致。正式服務商、運費、免運、取消與售後政策均未定案。
- **身份及營運模組 Identity／Operations**：保留訪客結帳與會員帳號能力；Owner、Merchandiser、Customer Support、Analyst 依最小必要權限操作。敏感操作、稽核欄位、高風險核准界線、MFA 適用對象、登入方式與資料保存期限待完整矩陣及資料政策。
- **內容模組 Content**：三語使用可索引的獨立網址，切換時保留有效購物車與 SKU。首頁品牌／商品入口屬首版；完整 Lookbook 與銷售轉換分析依 Phase 3 範圍另訂。
- **換裝模組 Fitting**：只使用商店事前準備的非 AI 固定資產；不建立個人照片、生成佇列、GPU 推論或額度依賴。角色／服裝建立正面、右側面、背面 View Set，不猜測看不到的背面，也不提供 360°。
- **角色資料**：男女各兩組具不同身體比例的成年標準模特；半寫實日系型錄插畫、適當中性 Base Garment。同角色不同 Body Size Profile 保持外觀識別；公布身高與必要圍度。優先評估 S／M／L／XL，正式支援尺寸以素材驗收結果決定。
- **相容性契約**：以角色身形 × SKU × 視角 × Asset Revision 的 Compatibility Matrix 控制展示；未審核、品質不符、授權不足、失效或停用的組合不可提供。只有經證明安全才能共用素材；顏色尺寸不得因素材共用而失真。
- **初始與選擇狀態**：初始為女性 A 正面 Avatar Introduction，沒有暗中預選角色尺寸。顧客明確選定 Body Size Profile 後進入換裝；角色尺寸與 Garment Size 分別選擇，不能代選訂單尺碼或推斷顧客本人特徵。
- **購買與展示邊界**：Product Availability 與 Fitting Availability 獨立。可購買性由商品、庫存與交易條件決定；圖片成功不能證明可購買。缺貨 SKU 可保留合格展示，但購買不可放行。後台可單獨停用換裝。
- **瀏覽與收藏模組 Outfit**：Fitting Session 保留當前角色、尺寸及視角；會員必須 Explicit Outfit Save 才建立 Saved Outfit，登入不自動保存。收藏記錄角色、角色尺寸、SKU、視角與必要版本，版本失效時明示無法重現或提供替代。最多 20 組是 PROVISIONAL，未確認前不當成硬性上限。
- **匯出與降級**：訪客與會員均可在相應權利範圍內下載 Outfit Reference Export，成果須明示品牌模特參考。素材載入失敗提供 Fitting Fallback，保留真實照片、尺寸表及正常購物。授權撤銷與停用須考慮公開快取撤除。
- **架構與 Schema 狀態**：上述是邏輯所有權，不要求微服務。尚無既有資料需遷移，也沒有已批准的 API、資料表、狀態機、錯誤碼或 CI Profile；不得將概念模型宣稱為正式契約。TypeScript 前台、商務平台、資料庫、換裝呈現與雲端候選保留為未選定。
- **待決而不新增承諾**：品牌網域、付款方式、保留期限、取消、折扣疊加、退款發票、運費免運、登入通知與保存政策，需補齊來源或取得決策。正式平台、金流物流發票選型及成本需同場景證據；本規格未執行最新能力、法規或價格查核。

素材外觀與授權另需人工審核證據；自動化路由或圖片載入成功不能代表自然外觀或合法授權。這些是品質驗收方法，不是新增內部程式接縫。
