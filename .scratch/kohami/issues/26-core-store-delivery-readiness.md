# 26: 核心商店獨立交付與啟用審查

**What to build:** 整合模擬交易、履約、權限、安全與復原證據及正式啟用延期清單，形成可審閱的 mock 核心商店候選成果，不依賴換裝完成。

**Blocked by:** 24：核心購物的手機、可及性與效能驗收；25：商務監測、安全與災難復原

**Status:** ready-for-agent

- [ ] 對指定候選版本彙整核心購物、付款競爭、退款、履約／發票、權限、合規與復原的實際證據及未通過事項。
- [ ] 停用或尚未提供換裝時仍可完成正常商品瀏覽、訪客／會員購物與售後，換裝素材不阻擋核心交付。
- [ ] 核對最終輸入、輸出、資料、事件及消費者影響，尤其語言切換、改價快照與付款／庫存／退款的一致性。
- [ ] mock 交付範圍、運費／人員權限機制、測試限制及正式服務資格／費率／人力延期清單可審閱，未決項不默認解決。
- [ ] 形成可供使用者核准的交付與啟用資料；本票完成不自動部署、正式收款或批准 Phase 2 啟用。

## 現行 mock 階段範圍（2026-10-13）

本票交付為mock核心商店的可審閱候選，無實際收款／寄送／開票。正式商家資格、真實費率、人員與供應商證據留延期清單，不阻擋mock交付；正式啟用仍另確認。

詳細以 [全流程mock政策](../proposals/04-demo-commerce-policy.md) 的 DEMO-01–12 為準；本節優先於以下完整產品／歷史來源中的真實服務或雙人退款要求。既有阻擋編號保留，按本階段契約是否完成判斷。所有新增產品案例仍 NOT_EXECUTED。

## 來源與範圍

- 階段：Phase 1 核心商店。
- 驗收對應：Phase 1；V01–V06、V11–V12；User Stories 85–87。
- 基準：KOHAMI 核心商店與模特換裝參考規格 v0.1（含 Comments）、產品規劃書、術語表、現行決策 D396–D446、驗證計畫及 ADR-0001；遵循 Round 18，有效決策不等於歷史編號總數。
- 先確認阻擋票均已完成；`ready-for-agent` 不解除依賴或重大待決條件。前置票須提供可審查證據並完成必要決策確認，不能把 UNKNOWN 或 PROVISIONAL 改寫成既定事實。
- 本票有實作時，按確認旅程補齊必要資料、介面、畫面、權限與錯誤行為，再驗證輸入、輸出、資料、事件及消費者影響；不拆成單獨的 schema／API／UI 層票。
- 沿用已確認測試接縫：瀏覽器端到端旅程為主；付款事件、庫存競爭與復原另用必要外部邊界驗證；素材品質及權利保留人工審核。執行前均屬 NOT_EXECUTED，不以圖片載入或工具成功當成所有驗收通過。
- 票單採用僅批准本機議題建立；後續工作依當次授權與必要決策執行。實作、付費／採購、素材製作、正式部署收款及換裝啟用不得僅由票單狀態推定授權；Phase 3／4 另案處理。
